DISENO DEL SISTEMA - DIAGRAMA DE SECUENCIA

Caso de uso modelado:
- Registrar reservacion individual

Objetivo:
- Mostrar la interaccion entre actor, frontend, backend y base de datos durante el registro de una reservacion, incluyendo la validacion de disponibilidad y la actualizacion del estado del cuarto.

Texto para Lucidchart:
- Crear un diagrama de secuencia para el caso de uso Registrar reservacion individual.
- Participantes: Recepcionista, Frontend Angular, API Reservaciones, Base de Datos.
- Flujo:
- El Recepcionista abre el formulario de reservacion en el Frontend Angular.
- El Frontend solicita clientes y cuartos a la API.
- La API consulta la Base de Datos y devuelve clientes y cuartos.
- El Recepcionista captura cliente, cuarto, fechas, descripcion y notas.
- El Frontend envia la solicitud de crear reservacion a la API.
- La API consulta en la Base de Datos el estado del cuarto seleccionado.
- Si el cuarto no esta disponible, la API devuelve error de conflicto y el Frontend muestra mensaje.
- Si el cuarto esta disponible, la API inicia transaccion.
- La API inserta la reservacion en la Base de Datos.
- La API actualiza el estado del cuarto a ocupado.
- La API inserta el registro en cuarto_reserva.
- La API confirma la transaccion.
- La API devuelve la reservacion creada al Frontend.
- El Frontend actualiza el listado y muestra confirmacion al Recepcionista.

Version PlantUML:
@startuml
actor Recepcionista
participant "Frontend Angular" as Frontend
participant "API Reservaciones" as API
database "Base de Datos" as DB

Recepcionista -> Frontend : Abrir modulo de reservaciones
Frontend -> API : GET /api/clientes
API -> DB : Consultar clientes
DB --> API : Lista de clientes
API --> Frontend : Clientes

Frontend -> API : GET /api/cuartos
API -> DB : Consultar cuartos y estados
DB --> API : Lista de cuartos
API --> Frontend : Cuartos disponibles

Recepcionista -> Frontend : Capturar datos de reservacion
Frontend -> API : POST /api/reservaciones

API -> DB : Verificar estado del cuarto
DB --> API : Estado del cuarto

alt Cuarto no disponible
  API --> Frontend : 409 Cuarto no disponible
  Frontend --> Recepcionista : Mostrar error
else Cuarto disponible
  API -> DB : Iniciar transaccion
  API -> DB : Insertar reservacion
  API -> DB : Actualizar cuarto a ocupado
  API -> DB : Insertar cuarto_reserva
  API -> DB : Confirmar transaccion
  DB --> API : Operacion exitosa
  API --> Frontend : 201 Reservacion creada
  Frontend --> Recepcionista : Mostrar confirmacion y refrescar listado
end
@enduml
